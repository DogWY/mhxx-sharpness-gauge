# MHGU 斩味条

适用于 macOS Astris 1.0.32 和 Switch 国际版《Monster Hunter Generations Ultimate》1.4.0。模块读取本地近战猎人的剩余斩味、上限和颜色，按游戏返回的档位边界绘制七色刀形 HUD。需要对应的 Title ID `0100770008DD8000` 和 Build ID 前缀 `FB08F1D20FD1204F`。

## 安装

退出游戏，解压 [MHGU-Sharpness-Gauge.zip](dist/MHGU-Sharpness-Gauge.zip)。在 Astris 游戏库右键游戏，选择 **Open Mods Folder → LayeredFS Mods**，将整个 `MHGU-Sharpness-Gauge` 文件夹放进去。在 **Manage Mods** 中启用，关闭 Forge 和旧 NRO 插件，再启动游戏。停用后重启游戏即可恢复。

安装后的 `MHGU-Sharpness-Gauge/exefs/` 包含 `subsdk2` 和以游戏 Build ID 命名的 IPS。支持斩味条单独运行，也支持搭配本机验证的独立伤害显示包（`subsdk1` 映射大小为 `0x5000`）。其他替换 `subsdk1`、`subsdk2` 或同一程序位置的 MOD 可能与它冲突。

## 构建

准备 Python 3、clang、liblz4 和 ld.lld（亦可使用 Rust 工具链附带的 rust-lld）。从该游戏版本导出含有原版 `main` 和 `subsdk0` 的 ExeFS，在仓库根目录执行：

```sh
python3 tools/build_mod.py /path/to/exefs
```

加上 `--check-damage-zip /path/to/MHGU-Damage-Display.zip` 可以检查伤害包是否占用 `subsdk2`、伤害模块的 NSO 头和段范围、映射大小以及双方补丁的写入区间。构建脚本校验两个原版模块的 Build ID、主程序代码哈希、三处补丁指令和两套模块布局的实际跳转目标。

需要在游戏内核对数值时，可用 `--diagnostic` 构建条下附有当前值、上限、档位的版本。`--probe` 用同一绘制入口显示固定方块，便于验证加载。三个版本占用同一模块槽位，每次只启用一个。

## 实现与验证

- [状态读取](src/sharpness.c) 根据 HUD 节点和本地玩家槽位判断显隐，读取猎人的当前值、上限和当前色。标准近战武器每次采样从当前装备的斩味表读取六个累计边界，第七段结束于斩味上限。
- [绘制](src/render.c) 按游戏实际呈现区域缩放 1280×720 的设计坐标，将刀身和各色段绘入已获取的画面纹理。
- [模块入口](src/entry.S) 支持斩味条单独加载与搭配伤害显示两种地址布局。采样线程通过双缓冲发布斩味和显隐状态，绘制回调读取最近一次完整发布的数值副本。
- Astris 的掌机模式、3× 分辨率下已验证同一个方块探针单独显示，以及和伤害显示同时初始化并绘制方块。状态回归测试覆盖本机非零玩家槽、消耗、跨档、磨刀和场景隐藏。绘制回归覆盖 720p 和 4K 的位置、最短色段和跨档。
- 2026-11-25，Astris 1.0.32 单独加载斩味条、关闭 Forge 后，开场无人输入运行至 16 分 20 秒并正常停止。该次测试使用武器分类修正前的构建。
- 修正盾斧分类后，在隔离存档的村六星任务「灼热之刃」中同时启用诊断版与伤害显示。盾斧进场显示 `300/300`、档位 `3`，战斗日志依次记录 `299 → 298 → 297`，画面读数亦为 `297/300`。切区时诊断日志先报告隐藏，再恢复显示。此次未取得同一击伤害数字与斩味变化的画面对照。
- 同日使用临时诊断包复验绿档与黄档的边界。诊断包只在任务开始时把斩味设为绿档最低值 `221/300`。与伤害显示同开时，战斗后读到黄档 `219/300`。单独运行斩味条时，命中后读到黄档 `220 → 219 → 218 → 217`。
- 单独运行时，诊断包预先选中道具袋中已有的普通砥石。手动按游戏使用键后，砥石数量从 20 减到 19，游戏提示「锋利度达到最大了！」，读数由黄档 `217/300` 恢复到绿档 `300/300`。测试包只设置起点和选中道具，三个分发包均不含这些写入。
